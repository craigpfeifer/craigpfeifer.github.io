Browser-based AirCube monitor

Open PR
StuckAtPrototype/AirCube · +1,176 lines · 6 files

The gap: the PyQt6 desktop app couldn't run on a Chromebook at all.

Root-caused it down to the hardware: pyserial saw no device because Crostini's kernel ships no cdc-acm module, and pyusb could open the device but never read from it — the ESP32-H2's USB Serial/JTAG gates TX until the host sends SET_CONTROL_LINE_STATE, which times out through ChromeOS USB passthrough.

Rebuilt the client on the Web Serial API with the DTR=0 RTS=1 handshake the chip requires — DTR=1 silently resets it, which was the real cause of a dead stream. Shipped with live AQI cards, three scrolling charts written directly to canvas with no charting library, CSV streaming, and device config round-trips.

Read-only mounts for smolfs

Open PR
CelestoAI/smolfs · +366 / −12 · 12 files · closes #14

The gap: nothing stopped an agent from writing to volumes holding model weights or evaluation data.

Added smolfs mount --readonly, enforced by the kernel through FUSE rather than by application-level checks. Read-only is modeled as a property of the mount, not the volume — set at mount, cleared at unmount — so it composes with the existing lifecycle. Threaded through the Rust core, the CLI status table, and both the Python and Node SDKs.

Backward compatible via #[serde(default)] so existing volume records still deserialize, with a regression test pinning it. Verified under cargo test, clippy -D warnings, fmt --check, and a maturin wheel build.

Orchestrating Dinner

celesto.ai · community blog
“The Chef Agent to have agency. It's time to add a layer.”

How a chef chatbot turned into a multi-agent system. Adding tools made it capable but opaque — “adding a tool to the mix increases complexity. How did I know what it was doing?” — so execution traces came first, then an orchestration layer to hold the memory the agent couldn't. The argument: keep the specialist focused on its own domain and let the orchestrator own persistence.
